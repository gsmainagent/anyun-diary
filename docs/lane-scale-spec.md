# 泳道非线性压缩 · 需求细化（2026-10-18，未实施）

## 0. 背景（owner 原话归纳）

- 现行 24h 线性泳道：一首 1 分钟的歌在 ~1100px 泳道里只有 ~0.8px 宽，根本点不中；空白（未开播时段）却占掉大半宽度。
- 决定：**泳道放弃时间线性**，压缩空白段，但**保留相对关系**（顺序/节奏/簇内比例）。
- **热力图保持时间线性**（日×时矩阵语义就是"几点在唱"，不能压缩）。
- **场次徽标全删**：录制文件断开 ≠ 多场，"N 场"是误导信息。

## 1. 场次徽标移除（独立小项，可先行）

| 位置 | 动作 |
| --- | --- |
| Timeline 左标签列「N场」徽标 | 删除（含 sessionCount 判定逻辑） |
| DayStrip 卡片「2 场」Chip | 删除 |
| 其余（日期/周几/歌数/时长/列表按钮） | 不动 |

## 2. 压缩算法（推荐方案：分段线性 piecewise）

### 2.1 构造（纯函数，输入当日歌曲区间列表 + 泳道像素宽 + 参数）

1. 歌曲按绝对时间排序、重叠合并（复用现状逻辑）
2. **聚簇**：相邻两首歌间隔 < M（默认 10min）→ 同一簇（簇内小间隔保持真实比例，这是"唱歌节奏"的一部分）
3. 簇 [cs, ce] 外扩 P（默认 3min）得活动段，clamp 到日界
4. 活动段之间、日首尾 → **压缩间隙段**

### 2.2 宽度分配

- 间隙段：固定宽 Wg（默认 24px；备选 log 缩放 16–56px，见开放问题 1）
- 活动段总宽 Wa = 泳道宽 − ΣWg，按**真实时长比例**分给各活动段（簇的相对长短保留）
- 尺度函数：xAt(t)/tAt(x) 分段线性，单调递增

### 2.3 可点性保证（核心痛点）

- 歌块视觉最小宽 **MINW=12px**：变换后不足者对称加宽，且不越过相邻块起点（密簇中允许低于 MINW，见 2.5）
- **命中区域 ≥ 视觉宽度 + 两侧各 6px padding，高度 = 整行 40px**（触屏友好）
- 悬停/选中态维持现行 tooltip（歌名/时长/绝对 HH:MM–HH:MM/来源）——**绝对时间信息转移到 tooltip 承载**

### 2.4 刻度与标注（非线性后小时轴不再等距）

- **删掉全局 HourAxis**（compress 模式下），否则刻度会误导
- 每个活动簇：左缘标起始 HH:MM（text-2xs）；簇整体 hover 显示「HH:MM–HH:MM · N 首」
- 间隙段：视觉用 ⋯ 或渐变省略样式；hover 显示「空 3h12m」类时长（平时不显示，减噪）
- linear 模式（兼容开关）保留现行 HourAxis

### 2.5 边界情况

| 情况 | 处理 |
| --- | --- |
| 全天无歌 | StateHint no-data（现状） |
| 连续密集 1 分钟短歌 | MINW 裁剪到邻居起点，允许 < MINW（罕见，可接受，文档注明） |
| 时长未知歌曲 | 按点事件处理：锚定起点渲染 MINW |
| 跨 00:00 | 沿用 shDayStart 日分组（现状） |
| 重叠歌块（同刻多文件） | 复用现状合并；MINW 加宽不越过合并块 |

### 2.6 参数表（初值，集中一处可调）

M=10min（聚簇阈值）/ P=3min（簇边距）/ Wg=24px（间隙宽）/ MINW=12px / hitPadding=6px / hit 高=40px

### 2.7 工程约定

- 纯逻辑放 `src/lib/lane-scale.ts`（不触 $env，遵守 vite-node 可测约定），单测 `scripts/test-lane-scale.mjs`（node 直跑）
- URL 参数 `?lane=linear|compress`，默认 compress（对比+回退保险；观察稳定后可移除 linear）
- Timeline 布局/交互其余部分不动；DayStrip/Playlist/Heatmap 不动
